## **6. Understanding the MongoDB Connection String (dbURL)**

This is another important part of the lecture.

In the previous lecture, we obtained the MongoDB Atlas connection string.

It contains the information required to connect to our MongoDB cluster.

For example:

```
mongodb+srv://username:password@cluster0.xxxxx.mongodb.net/
```

The instructor explains that this connection string must be supplied to the MongoDB configuration code.

However, there is a security problem with directly writing it inside the Python file.

### **Why should we not hardcode the MongoDB URL?**

Consider the following implementation:

```
db_url = "mongodb+srv://username:password@cluster0.xxxxx.mongodb.net/"
```

If this file is committed and pushed to GitHub, the connection string could become publicly visible.

Anyone who obtains the credentials might be able to connect to your database, depending on the permissions and network access configured.

This can expose your database to unauthorized access.

### **The solution: Environment Variables**

Instead of writing sensitive information directly inside the Python code, the instructor stores the MongoDB connection string in an environment variable.

The Python application then retrieves the connection string whenever it needs to connect to MongoDB.

**Hardcoded credentials vs environment variables**

**Hardcoded connection string**

Credentials are directly written inside Python source code and may accidentally be committed to GitHub.

**Environment variable**

Credentials are stored outside the source code and retrieved when the application runs.

**Key concept:** Sensitive information such as database URLs, passwords, API keys and access tokens should be kept outside publicly shared source code.

## **7. Creating the MongoDB Constant in the Constant Module**

The instructor has already created a folder named `constant`.

This folder is used to maintain constants and configuration values required throughout the project.

The MongoDB connection string will be retrieved from an environment variable inside this module.

### **Step 1: Open the constant file**

Navigate to:

```
shipment/constant/
```

Open the Python file inside it.

The instructor modifies this file to retrieve the MongoDB URL.

### **Step 2: Import&#x20;**`environ`**&#x20;from the OS module**

Add:

```
from os import environ
```

### **Understanding the&#x20;**`os`**&#x20;module**

Python's built-in `os` module provides functionality for interacting with the operating system.

One of its capabilities is accessing environment variables.

The `environ` object behaves like a dictionary containing environment variables.

For example:

```
environ["PATH"]
```

This retrieves the value associated with the `PATH` environment variable.

Similarly, we can retrieve our MongoDB connection string using its environment variable name.

### **Step 3: Define the MongoDB URL constant**

The instructor creates a variable named:

```
MONGODB_URL = environ["mongodburl"]
```

Here:

- `MONGODB_URL` is the Python variable that stores the retrieved connection string.
- `environ` accesses the operating system's environment variables.
- `"mongodburl"` is the environment variable key.

The key must match the name configured in Windows.

A complete illustrative implementation:

```
from os import environMONGODB_URL = environ["mongodburl"]
```

**How does this work?**

Suppose the Windows environment variable contains:

```
Key: mongodburl
Value: mongodb+srv://username:password@cluster0.xxxxx.mongodb.net/
```

When Python executes:

```
MONGODB_URL = environ["mongodburl"]
```

It retrieves the corresponding value and assigns it to `MONGODB_URL`.

This means the actual connection string does not need to be written directly in the Python source code.

Python variable names are case-sensitive. The environment-variable key must match the configured name. Windows environment-variable names are generally case-insensitive.

## **9. Accessing the Environment Variable from Python**

Once the environment variable has been configured, the Python application can retrieve its value.

The instructor's constant module uses:

```
from os import environMONGODB_URL = environ["mongodburl"]
```

This is essentially the same as dictionary access.

### **Understanding the dictionary analogy**

Consider a normal Python dictionary:

```
database_config = {    "mongodburl": "YOUR_MONGODB_CONNECTION_STRING"}
```

To retrieve its value:

```
db_url = database_config["mongodburl"]
```

Similarly:

```
db_url = environ["mongodburl"]
```

Here, `environ` acts like a dictionary.

- The key is the environment variable name.
- The value is the MongoDB connection string.

The instructor emphasizes that you only need to provide the key name in the Python code.

Python automatically retrieves the associated value from the operating system.

### **Why is this useful?**

Suppose you move your project to another system.

You do not need to modify your source code to replace the MongoDB URL.

You only need to configure the appropriate environment variable on that system.

This makes the project more portable and secure.

## **10. Important Step: Restart VS Code After Setting Environment Variables**

The instructor highlights one practical issue that can occur after configuring environment variables.

Sometimes, an already-running application does not recognize newly created environment variables.

### **Why does this happen?**

When an application starts, it generally receives a copy of the environment variables available to its parent process.

If you create a new environment variable while VS Code is already running, the existing VS Code process and its terminals may not automatically receive that updated environment.

As a result, Python might report an error such as:

```
KeyError: 'mongodburl'
```

This happens because Python cannot find the requested environment variable.

### **Solution: Restart VS Code**

The instructor recommends:

1. Close VS Code completely.
2. Reopen VS Code.
3. Open the Shipment project folder again.
4. Open the terminal.
5. Activate the required Conda environment.
6. Run the application or notebook again.

This ensures that the newly launched VS Code process receives the updated environment variables.

**Common mistake**

Creating an environment variable successfully does not necessarily mean an already-running VS Code terminal can access it.

Restart VS Code if the newly configured variable is not being detected.
